### ⚠️ 不经过网关的能力（要用百炼原生 API 直调）

你的百炼账号在 OpenAI 兼容模式下**只开放了对话和向量两个接口**（实测 `/images/generations`、`/audio/speech`、`/audio/transcriptions` 均返回 404）。视频生成已通过插件渠道接入网关，其余以下能力需直调百炼原生接口：

|---|---|---|
| 文生图/图编辑 | `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis`（异步任务） | `wanx2.1-t2i-turbo`、`wan2.7-image`、`qwen-image-2.0`、`z-image-turbo` |

| 实时语音/全模态 | WebSocket `wss://dashscope.aliyuncs.com/api-ws/...` | `qwen3-omni-flash-realtime`、`qwen3-tts-flash-realtime` |
| Rerank 重排 | `/api/v1/services/rerank/text-rerank/text-rerank` | `gte-rerank-v2`、`qwen3-rerank` |

文生图原生接口调用示例（异步：先建任务，再轮询）：

```bash
KEY="你的百炼 Key"
# 1. 创建任务
curl -X POST "https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -H "X-DashScope-Async: enable" \
  -d '{"model":"wanx2.1-t2i-turbo","input":{"prompt":"一只在月球上喝咖啡的猫"},"parameters":{"size":"1024*1024","n":1}}'
# → 返回 task_id
# 2. 轮询结果
curl "https://dashscope.aliyuncs.com/api/v1/tasks/<task_id>" -H "Authorization: Bearer $KEY"
```

## 一、这是什么 / 为什么选它

new-api 是一个 **LLM API 中转网关**：把多家模型厂商（OpenAI、Anthropic、DeepSeek、Gemini、火山方舟、硅基流动……）的 API 统一成一个 OpenAI 格式的接口，只暴露一个地址 + 一个 Key 给你所有的客户端，顺带做额度计费、用量看板、渠道负载均衡与故障自动切换。

选型对比（2026-09 实测）：

| 项目 | 定位 | 结论 |
|---|---|---|
| **QuantumNous/new-api** | 功能最全：计费、看板、多渠道、协议转换、中文文档 | ✅ **已选，本次部署** |
| yym68686/uni-api | 轻量自用，纯配置文件，无 Web 管理台 | 适合只要转发、不要界面 |
| BerriAI/litellm | 企业级网关，英文生态，偏重 | 团队/生产环境可选 |
| songquanpeng/one-api | 鼻祖，2025-02 后基本停更 | ❌ 新项目不建议 |

## 四、首次使用（5 分钟跑通）

### 第 1 步：初始化管理员

浏览器打开 **http://localhost:3000**：

- 若出现初始化引导页 → 按提示设置管理员账号密码；
- 若直接进登录页 → 用默认账号 `root` / 密码 `123456` 登录，**登录后第一件事是改密码**（右上角头像 → 个人设置 → 修改密码）。

### 第 2 步：添加上游渠道

「渠道」= 你真实付费/申请的那家模型 API。

路径：**控制台 → 渠道 → 添加渠道**

| 字段 | 怎么填 |
|---|---|
| 类型 | 选对应厂商，如 `OpenAI` / `DeepSeek` / `Anthropic` / `硅基流动 SiliconFlow` / `火山方舟` |
| 名称 | 随便起，方便自己认，比如 `DeepSeek-官方` |
| 分组 | 默认 `default` 即可（分组用来区分不同倍率/权限的用户） |
| 模型 | 填允许转发的模型，可用 `gpt-4o,claude-3-5-sonnet-20240620` 逗号分隔 |
| 密钥 | 上游厂商给你的 API Key，一行一个可填多个，会自动轮询、失败自动切 |
| 代理 | 国内直连不通时填，如 `http://127.0.0.1:7890` |

常用上游地址参考：

| 厂商 | 默认地址 |
|---|---|
| OpenAI | `https://api.openai.com` |
| DeepSeek | `https://api.deepseek.com` |
| 硅基流动 | `https://api.siliconflow.cn` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` |
| 月之暗面 | `https://api.moonshot.cn` |

填完点「测试」确认连通，再保存。

### 第 3 步：创建 API 令牌

路径：**控制台 → 令牌 → 添加令牌**

- **名称**：如 `CherryStudio`
- **额度**：填总金额或 `无限额度`（自用建议无限）
- **过期时间**：自用可留空
- **模型限制**：可限定只允许某些模型，留空=继承分组权限

保存后复制生成的 `sk-xxxxxx` —— **这就是你填进所有客户端的 Key**。

## 五、客户端接入

统一规则：

```
API Base URL / Base Path : http://localhost:3000/v1
API Key                  : sk-你在控制台生成的令牌
```

> ⚠️ 注意结尾的 `/v1`。有些客户端（Cherry Studio、NextChat）会自动补 `/v1`，此时填 `http://localhost:3000` 即可；有的（Claude Code、OpenAI SDK 手写）必须自己带 `/v1`。**如果报 404，就换另一种填法试。**

### curl 验证

```bash
# 列出可用模型
curl --noproxy '*' http://localhost:3000/v1/models \
  -H "Authorization: Bearer REDACTED"

# 发一条消息
curl --noproxy '*' http://localhost:3000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer REDACTED" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"你好"}]}'
```

> 本机开了代理时，`curl` 访问 localhost 必须加 `--noproxy '*'`，否则会被代理拦截。

### Python（OpenAI SDK）

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:3000/v1",
    api_key="REDACTED",
)

resp = client.chat.completions.create(
    model="deepseek-chat",          # 改成你渠道里配置的模型名
    messages=[{"role": "user", "content": "用一句话介绍你自己"}],
)
print(resp.choices[0].message.content)
```

### Node.js

```js
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:3000/v1",
  apiKey: "REDACTED",
});

const r = await client.chat.completions.create({
  model: "deepseek-chat",
  messages: [{ role: "user", content: "hi" }],
});
console.log(r.choices[0].message.content);
```

```bash
export ANTHROPIC_BASE_URL=http://localhost:3000
export ANTHROPIC_API_KEY=REDACTED
# 或 OpenAI 风格
export OPENAI_BASE_URL=http://localhost:3000/v1
```

## 九、常见问题

**1. 客户端连不上 / 超时**
先确认服务活着：`./start.sh status`。
再确认不是被系统代理拦了 —— 在客户端的代理设置里把 `localhost`、`127.0.0.1` 加入「不代理列表」，或临时关闭系统代理。

**2. 返回 404**
Base URL 结尾的 `/v1` 问题，见第五节。

**3. 返回 "Invalid token"**
Key 填错了，或者填的是上游厂商的 Key 而不是 new-api 控制台生成的 `sk-` 令牌。

**4. 上游返回超时 / 连接失败**
国内直连 OpenAI、Anthropic 不通。两种解法：
- 在渠道的「代理」字段填你的代理地址（推荐，只影响这一条渠道）；
- 或在 `start.sh` 里把 `HTTP_PROXY` / `HTTPS_PROXY` 的注释打开（影响全局请求）。

**5. 端口 3000 被占用**
```bash
lsof -i :3000          # 看是谁占用
PORT=3001 ./start.sh start
```

**6. 数据备份**
所有数据都在 `one-api.db` 这一个文件里，定期 `cp` 走即可。

**7. 想让局域网其他设备（手机/另一台电脑）也能用**
启动时加 `--host 0.0.0.0`（控制台 → 设置里也可配），然后用 `http://<你的内网IP>:3000/v1` 接入。注意：这样会暴露到局域网，务必把控制台密码和令牌管好。
